# PERF-1 changelog

## A note on version numbers

**0.13.0 is the first public release.** Its code is identical to the last development build, 0.12.8.

**0.14.0 is the second.** Its code is identical to the last development build, 0.13.15; the builds 0.13.1 to 0.13.15 in the git history are its steps.

**0.15.0 is the third.** Its code is identical to the last development build, 0.14.21; the builds 0.14.1 to 0.14.21 are its steps.

**0.15.1 is a fix-up of 0.15.0.** Its code is identical to development build 0.15.4; the builds 0.15.1 to 0.15.4 in the git history are its steps (the public number reuses the first of them).

**0.15.2 is a second fix-up.** Its code is identical to development build 0.15.5.

**0.16.0 is the fourth release.** Its code is identical to development build 0.15.27; the builds 0.15.6 to 0.15.27 in the git history are its steps.

**0.16.1 is the fifth release.** Its firmware is identical to development build 0.16.4; the builds 0.16.1 to 0.16.4 in the git history are its steps (the public number reuses the first of them). The Pieces and Library pages (0.16.3 and 0.16.4) are in the source but not on the website yet: they come with 0.17.

**0.16.2 is the sixth release.** Its firmware is identical to development build 0.16.16; the builds 0.16.5 to 0.16.16 in the git history are its steps. Its first reason is a fix: M-VAVE's new M-UPGRADE (3.11) could not find PERF-1, so there was no way back to the stock firmware with it. The Library & pieces page is in the source but not on the website yet: it comes with 0.17, with the boot stub (0.16.17) and a MIDI CC for every setting (0.16.18), which are on `vis`.

Before the first release the firmware was developed on two lines: a "main line" (0.3.x to 0.5.1) and an experimental `vis` branch that went through the numbers 0.4.0 to 0.12.8. The commit messages in the git history use those development numbers; they are all contained in 0.13.0. The leading 0 stays until PERF-1 reaches its first finished state, which will be 1.0.

The unit reports its version as `FM-1_7XXYYZZ` (0.13.0 is `FM-1_7001300`); the installer checks it.

## Unreleased (the builds 0.16.17 .. are its steps)

- **Newer FM-1s: saves and installs work** (0.16.23; issue #5, Niclio). FM-1s sold since autumn 2026 carry a UCUN UC25HQ80 flash (JEDEC 0xB36014) instead of the first units' Puya P25Q80 (0x856014): the same size and commands. PERF turned its flash on only for the Puya, so on a newer unit every save stayed in RAM (gone at power-off) and every install was refused ("stopped after 0 requests: nothing was written"; M-UPGRADE refused it too). Now both parts count (`FL_JEDEC_OK`, `firmware/hal/fm1_flash_id.h`, the same check as Melodee 1.6.0's); the sliced erase uses the UC25HQ80's suspend and resume (75h/7Ah) within its datasheet timings, and if a part ever refuses to suspend the blocking erase takes over as before. `tools/fm1_rescue.py` accepts both IDs (as felucca-bsp f690fa6). The status log says which part a unit has (the shed word's bits 12-13: 1 P25Q80, 2 UC25HQ80, 3 another; bit 14 an erase that didn't suspend): fm1log.py's `flash` and `susp_bad` columns, and the Install page's Live status beside the flash writes. The boot stub and the loader don't check the ID. Test: flash_id (both IDs on, none of the other 16M, the status codes). RAM +1 byte.

- **The timer interrupt runs from RAM** (0.16.22; the maker's 0.16.21 logs: FOREST at 79% with the shedding at level 3, which swaps the exact output clip for the cheap one and drops the Echoplex and the vinyl). The same piece cost 71% against 66% on 0.16.8, every stage a little slower, and the timer interrupt, whose code had not changed, 77 ms a second against 69 in every log before the boot stub's build: the code's move (body at 0x02001000) changed how flash code shares the cache. The interrupt fires 10,000 times a second and nests into the render, so from the flash it fetched itself cold and pushed the render's code out each time. Now `isr_timer5` and `fm1_timer5_irq` sit in `.ram_hot` (copied at boot, inside the PC guard's window) with the key matrix's tick, frame and debounce inlined into it (`FM1_IN_TICK`, `fm1_ticks` always inline); the USB, USB audio and TRS polls are called through pointers (RAM code cannot reach the flash directly). 1 KB of RAM code, three indirect calls; no change to keys, LEDs, USB timing or the loader (ota.bin byte-identical).

- **Pedal, and six more fills** (0.16.21; issue #3, Steven's chord chart and "harmonic drone followers"). **Fills:** black keys 6-11 on the Progression page write I IV V V, I I IV vi, I IV I V, I iii IV vi, I vi IV, IV V IV I (PGF, as the circle fills; the hint line names both sets). **Pedal** (amb.c pedal, bass_pc, en_pedal / C_PEDAL): white key 9 the bass, white key 10 the pad, follow the chords or hold the key. The bass on pedal holds the key's root (bass_to and the bass line's root; the walk walks the key's triad, deg_nat 2 and 4); the pad on pedal voice-leads to the key's chord (I, of the piece's or the slot's type) while en_chord keeps the harmony for the screens and the keys' lights; a switch retargets both at once. Kept as the player's, in the global record's last spare byte (glob.sl_rsv[2], bit 0 bass, bit 1 pad), stored at once, sent at boot; no piece byte (the banks have none). The keys are lit while on pedal and the page's last line says which. Host: en_bass_held, en_pad_held, expectations bassheld, padheldN. Tests: pedal.amb (the bass following A, D, then A under Dm and G on pedal, G again off it; the pad holding Am7, G A C E, under G7; kept through a reboot; three of the new fills slot by slot).

- **A knob on each setting: MIDI CC straight to any of the 176 settings, on any page** (0.16.18, a user's ask for a Launch Control XL 3, DAWless). Now an entry can be a setting: the Editor page's **Your controller** (Connect a controller, Learn, click a setting, move a knob or fader) learns it, and the Install page's Send to my FM-1 sends it with the panel controls (one list, localStorage hyp1-emu-midimap; 48 entries in all). On the FM-1 (ui.c mm_set): a fader or knob sets the value over the setting's range (0 .. 127, as Knob CCs do), an encoder (64 ± n, or 1 up / 127 down) steps it, through knob_set as a knob turn (the piece edited, a player's setting stored at once; the Mode through set_mode, so the scale follows); on the page that shows it its knob lights (ZOOM too), elsewhere its name and value show a moment. Encoding: bit 7 of an entry's first byte, the control byte the parameter; a map with settings is "MAP2" so an older firmware refuses it whole instead of taking a setting for a button (the Install page then says to update); old MAP1 maps load as before. RAM: none (the map's record is the same 152 bytes). - **A boot stub: an install cut off by a power cut comes back** (0.16.17, the maker's ask). ChoralRoot FM-1 v0.16's boot stub, as Melodee 1.3.5 ships it (version 3, byte for byte: its stub.lock SHA-256 baee55ed.. matches), credited in LICENSING.md. Why: the update loader counted on the flash copy of the update record to resume after a power cut, and ChoralRoot's hardware investigation (Melodee's BOOT-SAFETY.md) found that copy does not bring an interrupted install back; Melodee had a dark unit from one (2026-10-07). What it is: app.bin's first 0xEE0 bytes (flash 0x4120..0x4FFF) are the stub, which the SPL enters on every boot; the app proper (the body) is linked from XIP 0x02001000 (flash 0x5000; app.ld: 0x8C000 at most, below the marker's sector 0x91000; PERF-1's is 436 KB). The stub checks the 20-byte commit marker at flash 0x91FE0 ("CRBM", the body's length and CRC-32) and the body's CRC; a whole app boots; an incomplete one goes to the update loader kept at 0xE0000 (three key-light flashes: plug in and press Install again), or to the chip's USB boot if there is none or a hand-over already failed (one long flash). **OCT- alone held at power-on** asks for the loader on purpose (OCT- + OCT+ stays the panel setup). The loader now writes in the order that keeps that true: the marker's sector erased first, sector 0x4000 (the directory and the stub) only if it differs, the body, the marker last (ldr_core.c, Melodee's). Four compensation bytes after the marker keep app.bin's CRC-16 at 0x4352 (fm1pkg_make.py commit), so sector 0x4000 is the same bytes in every build and an ordinary install never touches it. The app keeps its own whole staged loader at boot (ota.c ota_staged, ota_boot_cleanup clears only the record's sector) and no longer erases it when an update is refused before staging (ota_touched). RAM: the stub owns 0x01C7C000..1F, NOINIT starts at 0x01C7C020; .data+.bss unchanged. Build: tools/build.py build_stub (Melodee's flags, the lock checked; a release refuses another stub). **The first install of 0.16.17 over an older PERF-1 rewrites sector 0x4000 once: a cut in those first moments is not protected** (16 of 1854 cut points in the model); every later install is (0 of 1837). Tests (Melodee's, ported): boot_stub_test (16143 checks), boot_stub_pkg_test (265), loader_powercut_test with boot_fixtures (a power cut after every erase and programmed page, each state given to the stub's own decision, then resumed to a bit-exact end), ota_test (the loader kept, the record cleared, a damaged staging erased, a refused update keeps it). **Not yet on hardware**: cold and warm boots, OCT- at power-on, a pulled cable and a power cut mid-install.

## 0.16.2 (the builds 0.16.5 .. 0.16.16 are its steps)

**In short.** M-UPGRADE 3.11 finds PERF-1 again, and goes from PERF-1 straight to M-VAVE's V16 as well as V15; the Install page's Back to the stock firmware takes V16's file too; the pages let go of the FM-1's MIDI port when they're done, so M-UPGRADE and music software can open it. Each chord slot of the Progression page can have its own type, with a new 11th chord, and chords are named right. Two visualizers: THEORY (the circle of fifths, the chord, its Roman numeral and what comes next) and TRIP. Auto FX plays the effects by itself, timed to the phrase. Your MIDI map on the FM-1 (experimental): what you learn in the emulator plays the FM-1 directly. Phrygian pieces reach the flat II, synthwave's major pieces play I-vi-IV-V, the walking bass leans in chromatically. Freeze from a sustain pedal. Fixes: a drum hitting itself no longer clicks; MIDI's all-drums mute mutes.

- **The pages let go of the FM-1's MIDI port** (0.16.16, the maker's M-UPGRADE runs). On Windows a USB MIDI port is one program's at a time, and the Install page kept the FM-1's from its first use until the tab was closed: M-UPGRADE said "A USB MIDI device is present but did not answer" (KsCreatePin error 1450) and music software could not open it. web/fm1idle.js (new): every MIDIAccess the page asks for is kept, and their open ports are closed after 4 s without FM-1 traffic, unless an install or write is running (writing) or the live status is on; the next button opens them again. The Install page and the Pieces page use it (the editor keeps its port while open: it sends every knob as it turns). Test: web_idle_test.mjs (kept while traffic flows or busy, closed when quiet, told once, opened again).
- **V16 both ways, on hardware** (2026-11-04, the maker's FM-1): 0.16.15 to M-VAVE's V16 with M-UPGRADE 3.11, and PERF-1 back on from V16 with the Install page.

- **Back to M-VAVE's V16 straight from PERF-1** (0.16.14, 0.16.15; the maker's unit). M-UPGRADE 3.11 offers M-VAVE's new **V16** (FM-1_016, 718176 B). Its boot head (flash.bin's first 16 KiB) differs from V15's in 12655 bytes, and the update path (Felucca's ota_stage) let the official loader rewrite the head only when it equals the unit's: it read the head, refused (-5), showed UPDATE FAILED and went back to PERF-1, and M-UPGRADE timed out ("wait for a firmware request", error 258); V15 went through. Now the head may also change between M-VAVE's two, V15 (CRC-32 3A04AD23) and V16 (08316064), both ways, as M-VAVE's own V15 -> V16 update does (the same official loader, its CRCs checked as before); any other head that differs is still refused, and the screen then says UNKNOWN BOOT HEAD. INSTALL STOCK V15 FIRST, THEN UPDATE FROM STOCK for 6 s (main.c ota_show, the watchdog fed). The loader builds as before (#ifdef FELUCCA_LOADER: 7576 B, byte for byte). The Install page's Back to the stock firmware takes V16's file too (its SHA-256). Tests: ota_test PKG DEVICE (by hand, with M-VAVE's files, not in the repository): V16 onto a V15 head, V15 onto V16, each onto itself: staged and committed (76 requests); one byte of the unit's head changed: refused (-5), nothing committed.

- **M-UPGRADE finds PERF-1 again** (0.16.13; issue #5, and the maker's unit): M-VAVE's M-UPGRADE 3.11.0318 (built 2026-11-03) checks the identity a device answers to its handshake against `[^_\t\r\n]+_[0-9]{1,3}` (its log: "Invalid device identity") and PERF-1's is FM-1_7XXYYZZ, seven digits, so it said "A USB MIDI device is present but did not answer" and no other firmware could go on from it. The plain handshake (M-UPGRADE's) now gets the model and family only, FM-1_700, as AMB-1 and HYP-1 answer; the handshake with the one-byte body 01 gets the whole identity (ota.c ota_is_hs, ota_reply_identity). PERF-1's installers (web/fm1ota.js, tools/fm1_install.py) ask that way when the answer is FM-1_7 and three digits, so they still read the version and check it after an install; the stock firmware, the loader and older PERF-1 builds are asked as before. Tests: ota_test (a long identity: the plain query gets 8 characters, 01 the whole), install_test (a PERF-1 that answers both ways), web_ota_test.mjs (new: the web handshake against PERF-1 old and new, AMB-1, stock and the loader). **On the maker's FM-1 (2026-11-04):** M-UPGRADE 3.11 received FM-1_700, "Compatible devices found: 1", and started an upgrade to M-VAVE's FM-1_016 (its read requests answered). A browser page holding the port (the Install page) gives KsCreatePin error 1450 instead: one program at a time.

- **Fix: MIDI's "all drums muted" did not mute** (0.16.12, the maker's report): pad 7 of bank A on MIDI in (Notes: PADS, and the MPK's bank A) flipped the mutes and said MUTE ALL DRUMS, but never told the engine (en_trk), so the drums played on; the panel's way (GLO + the keys) did. pads.amb now checks the engine's own mutes (en_trk_heard, expect entrkmute).

The MPC's knobs and fader send no MIDI in its stock software (SAMPERF's link mode sends them: CC 16-18, 20, the wheel CC 100), so the MIDI map on the FM-1 is marked experimental for now.

- **Auto FX** (0.16.8), the idea after DARK-1's Auto FX (by Polystellarflow), rebuilt for PERF-1's sections and genres (ui.c af_tick, no code taken): a settings page after AUTO DJ (Auto FX: off, gentle, medium, wild; Every: 4, 8, 16, 32 bars; Length: a beat, half a bar, a bar, two bars; Pick: the genre's own first, or any; EN_FXS_AF_* 92-95, kept with the effects' settings; page bit FX_SPARE12). - **Three savings on the first core, from the 0.14.3 log** (0.14.4): the pad now reaches the mix a chunk late (5.8 ms, as the DX voices have since 0.10), written to a ring by the second core and read a chunk on, so the first core never waits for it and the chorus always runs on the second core (in 14 of 24 pieces logged the balancer had moved the chorus to the first core for good, 250-330 us a chunk, 7-8 points, while the second sat at 30 %; in the others the wait cost 80-250 us); the vinyl's noise is made every other sample and held, and its ticks and dust decided every fourth, at the same odds (it cost 324 us a chunk, 10 points, in every genre with the vinyl latched; the hold's roll-off sits under the Tone low-pass); the once-a-chunk control runs at most once per 128 frames, so a short chunk cut for a swung hit skips it (210-260 us a call whatever the length). The pad's stabs land 5.8 ms later than before, as the pluck's DX voices do. The log's pieces (padmix, w_pad, noise, r_control) say what each one gave. (The bass, about 200 us a chunk whatever the length, was to render from RAM as an experiment; the chip's call reach from RAM to the flash stopped that for now, the linker's `.ram_hot` section stays for a call-free candidate.)
- **Where a chunk's fixed cost goes** (0.14.3): 0.14.2 on the unit: LOFI 6, 356 s, no late render (23 in 377 s before), the slowest halves now five chunks at 11.0-11.3 ms, so the fix held but the margin is thin, and those halves say a chunk costs about 1 ms whatever its length, a quarter of a normal half. The status log's second frame now also sums the stages of the chunks shorter than 256 frames apart from the full ones, with their count and frames, so `tools/fm1sum.py` can solve each stage's fixed cost from any log ("fixed cost a chunk by stage"). A third frame (`F0 7D 50 5B`) times fourteen pieces inside the stages (bass, acid, pluck, DX voices, snips, noise, the pad merge, the sidechain, drums, the bass merge, echoes, the performance effects, the dynamics, the clip), counts the chunks by size and splits the work between chunks (drain, control, pulse, hits). A diagnostic build: about thirty clock reads a chunk more than before. Nothing in the sound changes.
- **The 12 ms halves were halves cut into too many chunks** (0.14.2): 0.14.1's log showed every slow half (12 to 13.7 ms) rendered in 7 to 9 chunks where the usual half takes 2 or 3, with the stages adding up to 10-11 ms against 7. The engine cuts its render at every hit that waits for its swing or humanize offset, and on a swung step the hats, perc, pluck, acid and bass line each waited a different few milliseconds, so each got a chunk of its own; on the device every chunk costs a fixed share whatever its length. A hit that would cut a chunk shorter than 128 frames now sounds at that mark instead, up to 2.9 ms later than its offset asked (those hits are 6-60 ms off the grid by design); a 256-frame render is at most three chunks for the hits. The clock pulse still cuts exactly where it falls, so the grid and the MIDI clock out are unchanged. Said plainly: the slow halves were not one slow thing but the same work done nine times over.
- **The slowest half, dissected** (0.14.1): the 0.14.0 logs showed halves of 12-13 ms whose slowest chunk was under 4 ms, so the time is going somewhere the stage timers do not see. The status log's second frame now carries, for each window's slowest half, its length, the sum of its chunks' stages, its waits for the second core, the timer interrupt's time inside it, its chunk count, the step it began at and what the main loop was doing (`pkr_*` columns; `tools/fm1sum.py` prints "the slowest halves"). Older loggers ignore the extra words; the new logger reads older firmware. Nothing in the sound changes.

## 0.14.0 (the builds 0.13.1 .. 0.13.15 are its steps)

- **The xruns were a lost interrupt** (0.13.15): the audio interrupt cleared its flag after the render. A render that ran past its half (11.6 to 12.4 ms in a lofi piece at 55 % load) therefore cleared the flag the next half had already raised: that half was never rendered and its buffer played a second time. Each xrun in a 309 s log was exactly one render missing from the renders count. The flag is now cleared before the render, so a late render is followed at once by the next one and nothing is lost; `XR` counts only halves never rendered, `late` (new in the status log and the installer's Live status) counts renders that ran past their half. Load shedding follows: one step at a time (a single overrun used to climb s0 to s3 in under two seconds), on a lost half, or on six late renders in ten seconds. The installer's status CSV also records the slowest chunk of each window and the histogram of render times. On the unit: the same lofi piece, 9 xruns in 309 s before, 0 xruns in 642 s after (88 late renders, the longest 13.3 ms, absorbed).
- **Steps page** (0.13.1): a ratchet (x2, x3, x4, x6, flam, swells), a push (late, in twelfths of a step) and a level (ghost, soft, accent) for each step of each lane, stored with the piece in the record's spare bytes (older pieces load with none); some genres ship with tricks.
- **Bass line page** (0.13.2): the drone as notes (Root, Kick, Eighths, Off-beat, Walk, Riff) with Length, Move and Glide, a genre's own rhythm and riff; lofi, house, dubstep, electro, trap and the newer genres start as a bass line.
- **Deja vu page** (0.13.3): the pluck remembers its last 4 to 32 notes and brings each round again with a chance (Deja vu, Loop, Leaps); Acid mut chooses what the acid's Mutate changes (all, notes, rhythm, accents).
- **Feel page** (0.13.4): the genre's ghost notes, how much accents and ghosts count, the pad's comping rhythm (auto, hold, seven rhythms), humanize; per-genre comping, ghost steps and accents.
- **Six more genres** (0.13.5): disco, funk, reggae, synthwave, amapiano and trip-hop, sixteen in all, each with its own flash object.
- **Phrase page** (0.13.6): a chain of patterns by bar (nine presets, the Amen's 1 1 3 4 among them), eight slice permutations of the drum steps (and an automatic one), half and double time, and a condition for each drum lane (odd or even bars, first or last of four, first of eight, fills only, not in fills).
- **Backup and restore** (0.13.7): the installer page saves everything the FM-1 has stored (pieces in every genre, settings, DX7 voices, theme, Tune, MIDI out) to a `.p1bak` file and puts it back, so switching firmware does not lose it. SysEx messages `7D 50 42`/`43`/`44`; each store is checked as its loader would take it, then written through the usual A/B commit, and the unit restarts.
- **Dub replaces Jungle** (0.13.14): the fifth genre is now DUB (pieces V01-V10, 64-76 BPM): one-drop, steppers and rockers patterns, a deep bass on the one and three with long notes, the skank on the off-beats, a long dotted-quarter echo, a worn tape latched on, a minor one-four vamp, and a breakdown that keeps the kick. Jungle's heavy ratchet-and-chop drums cracked the first core in every measurement. Pieces stored in that genre's slot keep their old settings under the new name (reset the bank, or store them again, to hear Dub).
- **Sections shaped by genre** (0.13.13): the bar before a breakdown thins out (percussion, open hat and half the hats go) so the break is a release, not a cut; a breakdown keeps the kick in house, techno and dubstep and the hats in drum and bass, darkens the whole mix a little, and raises the pad less in trap, dubstep, lofi and trip-hop; a build is two bars in trap, lofi and trip-hop, eight in house, otherwise four, with the snare climbing a fifth, the open hat on every eighth in the last bar and, in the four-on-the-floor genres, the kick back before the drop; the drop's open hat is a crash that rings and the chord goes home most of the time; and drum fills are one of six (the old ramp and five new ones) instead of always the same snare roll.
- **Fourteen new Flex Beat patterns** (0.13.13): Jump bk, Halves, Swap, Mirror, Lag, Slowmo, Skip 3, Stut up, Stut dn, Tresillo, Offbeat, Cut 4, Rev 8 and Half gap, so every one of the 27 keys has a pattern. Stut 16 and Stut 32 are gone (the beat page's repeats do the same).
- **DX voice levels by loudness** (0.13.13): the sustaining DX voices (pads, strings, brass, electric pianos, bells, bass, sax, ...) sit 8 dB lower against the plain plucks; the percussive ones (marimba, kalimba, wood bars, steel guitar, slap bass) stay; loaded voices play at half level. A first guess from the audit's measurements: say if one is still too loud or now too soft.
- **A third shed step for the first core** (0.13.13): if a piece still cracks after the drone and acid have moved to the second core and the DX voices are capped, the engine now also drops the Echoplex slap, the vinyl noise and uses a cheaper output clip (about 2.5-4 points of the first core), and eases back after 20 s without a crack like the other steps. Aimed at heavy pieces with no DX voices to cap, such as Jungle.
- **Overload moves work to the idle core first** (0.13.13): when a piece starts to crack and the engine begins shedding, the drone and the acid now go to the second core (it sits at 25-30 % in the pieces that crack) before any quality is given up; they come back if the first core ends up waiting for it. Before, shedding also pinned them to the busy first core.
- **DX voices off the critical path** (0.13.13): the first core waits for the second's reverb tank and no longer for its DX voices; those now render while the first core does its master effects, compressor and limiter, and are joined at the end of the chunk. Aimed at the xruns that only ever showed in DX-pluck pieces; the sound is bit-for-bit the same. A core lost at the drone-and-acid wait is now retired before its half-written buffers are read.
- **Swing and looseness for every voice** (0.13.13): the acid, the bass line and the pad's stabs follow the Swing setting with the drums and the pluck (they used to play straight against swung hats in Garage, Lofi, Amapiano, Reggae and Funk), and Humanize loosens each by a few milliseconds (acid 6, bass 4, stabs 8 at 100).
- **Chord habits per genre** (0.13.13): each genre has its own moves between chords (ii-V-I for lofi, amapiano and disco, i-VII-VI-VII for house, i-VI-III-VII for synthwave, the i-IV vamp for funk and reggae), a pull home, no A-B-A turn-back where it does not belong, and a cadence at the end of each phrase of four (or eight) chords. Before, every genre was close to the same random walk.
- **Flex Beat takes one FX bit** (0.13.13): the pattern is a number sent to the engine, so the 14 bits it used are free and the Flex bank can grow past fifteen patterns. Nothing changes in use.
- **Safer holds and the FX menu** (0.13.13): factory reset is now SEL + SAVE held on Global (SAVE alone only stores, so a long press can no longer wipe a piece); GLO's mix map comes at 0.4 s like the other holds; a page's button closes the FX menu; HOME + SELECT sets the tempo inside the FX menu; OCT- resets the mix only on the FX keys page.
- **Fixes from the audit** (0.13.13): Flex Beat slices below 126 BPM keep the pattern's shape (Half repeat, Double and Back-forward no longer play in a scrambled order at slow tempos); a pushed hit on a swung step is no longer lost when the next step also waits; the swung pluck note no longer sounds after Stop or Panic; SAVE during a restore no longer cancels it.
- **Acid steps page and freeze** (0.13.12): the acid line shown as sixteen steps you can edit (rest, note, accent, slide, note, octave), frozen so Mutate leaves it, and stored with the piece (18 bytes in the record's spare room).
- **Eight new DX voices** (0.13.11): steel, clean, muted and drive guitars, slap bass, synth brass, sax and muted trumpet (thirty built in); the player's own voices shift up eight places in stored pieces and are renumbered when an older piece loads.
- **Seamless saves** (0.13.9): a flash erase in slices with the chip's erase-suspend command, so a store while playing no longer fades the music; the old fade and blocking erase come back if the chip cannot suspend.
- **Fixes** (0.13.8): the new genres' effect tables, a limiter made safe against a bad sample, vinyl crackle, drone renamed bass everywhere, a battery indicator, long knob values fit their card.
- Ideas from **Tuna** by delirioux (GPL-3.0), written afresh for PERF-1's engine; credited in the manual and LICENSING.

## 0.13.0

What the development builds added, in the order they came (the numbers are the development builds):

- **0.3 - 0.4:** the main line's pieces, FX menu and performing tools; then rolls and STAGE, a texture layer, easier menus, the JAM page, six more genres (jungle, DnB, breaks, garage, electro, trap), and the sequencer's tricks (Euclid, rotation, probability).
- **0.5 - 0.7:** the plate reverb on the FM-1's second core, then the pad as well; a six-operator FM engine and 22 DX7-style voices for the pluck.
- **0.8 - 0.9:** the master bus (compressor and limiter), the Mixer page with meters; the pad's chorus; reverb types (plate, shimmer, gated); the auto-DJ's drop, fill and SYNC; the full-screen screensaver and visualizers; load shedding; DJ snips; settings that are remembered; polymeter.
- **0.10:** USB telemetry (a status log over MIDI) and a long run of measurements and fixes that made the heavy pieces (DnB, jungle) hold their audio: a smarter second core, integer FM buses, a cheaper master stage.
- **0.11:** load your own DX7 voices (`.syx`) over USB; the web editor with a DX7 voice editor; crash fixes found in testing; a review of the whole firmware and its fixes.
- **0.12:** the **Groove** page (lane density, per-lane source pattern), held pattern keys, a chord loop, scenes that carry the groove; **the sigil** in the middle of the home screen; the **Imp** look in six palettes; each genre's own chord habits; **the acid answer** (nine kinds, up and down, every 2nd to 8th bar or loop, or before the drums change); **storage that keeps a piece in every genre** (a packed 376-byte record per piece, a flash object per genre); new air and rave horns; a pump that can follow the kick; many sound and timing fixes (the vinyl, the drop, the save pause).

Each development build is one commit in the git history, and its message says what it changed.
